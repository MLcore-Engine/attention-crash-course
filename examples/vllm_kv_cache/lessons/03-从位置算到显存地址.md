# 第 3 课 从位置算到显存地址

本课沿 V1 的 CUDA FlashAttention 后端，追到实际 writer 和 reader。页大小继续取 16，A 的块表最初为 `[1,2]`。需要生成逐行 CPU 状态时运行 `lifecycle_demo.py`。

## 先分清三个数字

| 名字 | A 第 17 个输入 token 的值 | 含义 |
|---|---:|---|
| token id | 17 | 词表中的编号，本例只是手造整数 |
| position | 16 | 在 A 序列中的位置，从 0 开始 |
| slot | 32 | GPU 缓存中供这个 token 使用的位置 |

token id 决定模型输入。position 决定序列位置与 RoPE。slot 决定 K/V 被写到哪一页、哪一个 token 格子。

## position 怎样变成 slot

worker 对每个本轮待算 token 计算 position。每个 token 先归属于某个请求行，position 为该请求已计算长度加上本步内部偏移。 [position 构造](../upstream/source/vllm/v1/worker/gpu_model_runner.py#L950)

```python

                                   positions // self.block_size)
```

| 源码行 | 逐行理解 |
|---|---|
| 106 | 这里走单 DCP rank 的分支。 |
| 107～108 | 在展平的二维块表里定位条目，公式为 `请求行号×每行最大块数 + position//16`。 |
| 109 | 读出该位置对应的物理块号。 |
| 110 | 计算页内偏移，为 `position%16`。 |

| 115～116 | 将块表整数矩阵复制到 GPU，供读取历史 KV 使用。 |
| 118～119 | 将本轮写入位置复制到 GPU，供 writer 使用。 |


把 A 的实际数字代进去。

```text
A 块表                  [1,2]
position                 16
逻辑块号                 16 // 16 = 1
物理块号                 A.blocks[1] = 2
块内偏移                 16 % 16 = 0
slot                     2 × 16 + 0 = 32

全部 prompt 的 slot      [16,17,…,31,32]
下一轮 position 17       slot 33
```

多个请求的 token 可以一起打包。例如 A 已长到 33，B 共享 A 的第一页但有自己的尾页，块表如下。为了展示展平索引，每行预留四个条目。

```text
row 0 / A    [1,2,4,0]
row 1 / B    [1,3,0,0]

本步算 A.position=32 与 B.position=16
req_indices               [0,1]
positions                 [32,16]
block_table_indices       [0×4+2, 1×4+1] = [2,5]
block_numbers             [4,3]
block_offsets             [0,0]
slot_mapping              [64,48]
```

源码第 292～327 行。[source/csrc/cache_kernels.cu](../upstream/source/csrc/cache_kernels.cu#L292)

<!-- source: upstream/source/csrc/cache_kernels.cu:292-327 -->
```cpp
  const int64_t token_idx = blockIdx.x;
  const int64_t slot_idx = slot_mapping[token_idx];
  // NOTE: slot_idx can be -1 if the token is padded
  if (slot_idx < 0) {
    return;
  }
  const int64_t block_idx = slot_idx / block_size;
  const int64_t block_offset = slot_idx % block_size;
  const int n_elems = num_heads * head_size;

  // pointers to the beginning of the source row for this token.
  const scalar_t* __restrict__ key_src = key + token_idx * key_stride;
  const scalar_t* __restrict__ value_src = value + token_idx * value_stride;

  // find the start position inside the kv-cache for this token.
  cache_t* __restrict__ key_dst =
      key_cache + block_idx * block_stride + block_offset * page_stride;
  cache_t* __restrict__ value_dst =
      value_cache + block_idx * block_stride + block_offset * page_stride;

  // this is true for the NHD layout where `head_stride == head_size`
  const bool is_contiguous_heads = (head_stride == head_size);

  float k_scale_val = (kv_dt == Fp8KVCacheDataType::kAuto) ? 0.f : *k_scale;
  float v_scale_val = (kv_dt == Fp8KVCacheDataType::kAuto) ? 0.f : *v_scale;
  constexpr int VEC_SIZE = (sizeof(scalar_t) == 2) ? 8 : 4;
  CopyWithScaleOp<cache_t, scalar_t, kv_dt> k_op{k_scale_val};
  CopyWithScaleOp<cache_t, scalar_t, kv_dt> v_op{v_scale_val};
  if (is_contiguous_heads) {
    // NHD layout
    // kv cache: [num_blocks, block_size, num_heads, head_size]
    vectorize_with_alignment<VEC_SIZE>(key_src, key_dst, n_elems, threadIdx.x,
                                       blockDim.x, k_op);

    vectorize_with_alignment<VEC_SIZE>(value_src, value_dst, n_elems,
                                       threadIdx.x, blockDim.x, v_op);
```

| 源码行 | 逐行理解 |
|---|---|
| 292 | `blockIdx.x` 是本轮打包 token 的索引。A prefill 17 个 token 时取 0～16。 |
| 293 | 取这个 token 的目的 slot。A 最后一个 prompt token 的 slot 为 32。 |
| 295～297 | 负 slot 是 padding 或该 rank 不负责的位置，跳过写入。 |
| 298 | `32/16=2`，恢复物理页号。整数除法。 |
| 299 | `32%16=0`，恢复页内 token 偏移。 |
| 300 | 本 token 每种 K/V 有 `2×32=64` 个元素。 |
| 303 | 找到输入 K 中本 token 的起点。 |
| 304 | 找到输入 V 中本 token 的起点。 |
| 307～308 | 找到缓存 K 中该物理页、该 token 的起点。 |
| 309～310 | 缓存 V 同样寻址。 |
| 313 | head stride 等于 head_size 时，当前 token 的所有 head 连在一起，进入 NHD 分支。 |
| 315～316 | auto 精度无需 FP8 缩放，缩放值设为 0，转换分支会忽略它。 |
| 317 | 16 位输入使用每组 8 元素的向量拷贝粒度，其余使用 4。 |
| 318～319 | 建立 K/V 的复制或量化操作对象。 |
| 320 | 分支选择 NHD。 |
| 323～324 | 各线程协作复制本 token 的 K，按对齐条件向量化。 |
| 326～327 | 对 V 做同样的操作。 |


`CopyWithScaleOp` 的 `kAuto` 分支做类型转换后的复制，FP8 分支调用 `scaled_convert`。它与上述 kernel 都在同一个原始文件内。 [复制与量化](../upstream/source/csrc/cache_kernels.cu#L267)

现在追一个元素。NHD 下每层的单独 K buffer 为 `[8,16,2,32]`，元素 stride 为 `[1024,64,32,1]`。

```text
目标元素    A.position16 的 KV head 1、dim 3
物理坐标    K_cache[2,0,1,3]
元素偏移    2×1024 + 0×64 + 1×32 + 3 = 2083
BF16 字节偏移    2083×2 = 4166
```

因此写入可以理解为 `*(K_buffer_start + 4166 bytes) = 本层这个 token 的 K[1,3]`。V 有自己的 buffer 起点，同一组坐标采用同样的 NHD 偏移。

如果本轮 K 输入连续，`key_stride=64`，输入元素偏移为 `16×64+1×32+3=1059`。实际模型从 QKV 大张量切出来的 K 可能不连续，代码使用 `key.stride(0)`，需要代入实际 stride。

### HND 分支怎样处理 head 间的间隔

源码第 329～352 行。[source/csrc/cache_kernels.cu](../upstream/source/csrc/cache_kernels.cu#L329)

<!-- source: upstream/source/csrc/cache_kernels.cu:329-352 -->
```cpp
  } else {
    // HND layout: heads are strided, but each head_size segment is contiguous
    // kv cache: [num_blocks, num_heads, block_size, head_size]
    const int lane = threadIdx.x & 31;     // 0..31 within warp
    const int warp_id = threadIdx.x >> 5;  // warp index within block
    const int warps_per_block = blockDim.x >> 5;

    for (int head = warp_id; head < num_heads; head += warps_per_block) {
      const scalar_t* __restrict__ k_src_h = key_src + head * head_size;
      const scalar_t* __restrict__ v_src_h = value_src + head * head_size;

      cache_t* __restrict__ k_dst_h =
          key_dst + static_cast<int64_t>(head) * head_stride;
      cache_t* __restrict__ v_dst_h =
          value_dst + static_cast<int64_t>(head) * head_stride;

      // within each head, let the 32 threads of the warp perform the vector
      // copy
      vectorize_with_alignment<VEC_SIZE>(k_src_h, k_dst_h, head_size, lane, 32,
                                         k_op);

      vectorize_with_alignment<VEC_SIZE>(v_src_h, v_dst_h, head_size, lane, 32,
                                         v_op);
    }
```

| 源码行 | 逐行理解 |
|---|---|
| 329～331 | 进入 HND 的实际存储顺序，语义上依然使用相同的物理页号和 position。 |
| 332 | 取 warp 内 lane 编号。 |
| 333～334 | 取线程所在 warp 编号和当前 CUDA block 中的 warp 数。 |
| 336 | 把不同 head 分给 warp。 |
| 337～338 | 本 head 在源 K/V 中的起点。 |
| 340～343 | 按 head_stride 跳到该 head 在缓存里的起点。 |
