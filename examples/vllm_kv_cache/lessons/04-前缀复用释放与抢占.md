# 第 4 课 前缀复用、释放与抢占

继续追第 2 课的 A 和 B。A 的前 17 个 token 为 `1,…,17`，B 为 `1,…,16,777`。每块 16 个 token，所以它们的第一页完全相同，尾页分别有一个不同的 token。

## hash 怎样描述一段完整上下文

请求创建与追加 token 时会增量计算完整块的 hash，入口为 `get_request_block_hasher`。它每次推进一个 block_size，遇到不满一页的尾部就停止。多模态、LoRA、cache salt 等额外键由 `generate_block_hash_extra_keys` 产生。 [增量计算](../upstream/source/vllm/v1/core/kv_cache_utils.py#L576) · [额外键](../upstream/source/vllm/v1/core/kv_cache_utils.py#L517)

源码第 567～573 行。[source/vllm/v1/core/kv_cache_utils.py](../upstream/source/vllm/v1/core/kv_cache_utils.py#L567)

<!-- source: upstream/source/vllm/v1/core/kv_cache_utils.py:567-573 -->
```python
    if not parent_block_hash:
        parent_block_hash = NONE_HASH

    curr_block_token_ids_tuple = tuple(curr_block_token_ids)
    return BlockHash(
        hash_function(
            (parent_block_hash, curr_block_token_ids_tuple, extra_keys)))
```

| 源码行 | 逐行理解 |
|---|---|
| 567～568 | 第一块使用初始化过的 NONE_HASH 作为父 hash。 |
| 570 | 把当前块的 token id 固定为 tuple。 |
| 571～573 | 对「父块 hash，当前块 token id，额外键」一起计算 hash。父 hash 把更早的上下文串进来。 |


在本例里，第一页为 `h0 = hash(seed, (1,…,16), None)`。A 与 B 的 h0 相同。A 后来长到 33 个已计算 token，第二页为 `h1 = hash(h0, (17,900,…,914), None)`，第三页只写了 915，尚不满页。

相同的 16 个 token 如果接在另一段不同的历史后，父 hash 会变化，KV 前缀查找也随之变化。

CPU demo 从原始文件加载并执行这里的 hash 函数和 `sha256` 函数，固定 NONE_HASH 为 32 个零字节以复现教学状态。实际 vLLM 的 seed 初始化在同文件 `init_none_hash`，序列化的 hash 字节还受 Python pickle 版本影响，demo 断言的是共享关系。

### 把「减一并整页对齐」算到具体数字

假设所需完整前缀都已存在，仍使用 16 token/block。

| 当前请求长度 | 允许命中长度 = 长度−1 | 最多命中整页 token | 至少重算的 token 数 |
|---:|---:|---:|---:|
| 16 | 15 | 0 | 16 |
| 17 | 16 | 16 | 1 |
| 32 | 31 | 16 | 16 |
| 33 | 32 | 32 | 1 |

缓存保存 K/V。重新执行末 token 的 forward 后，才能继续得到 hidden state、logits 和下一次采样。上表是这个固定版本、full attention、整块匹配条件下的代码结果。

## 已进入空闲队列的页怎样再次复用

C 具有与 B 相同的 16 token 前缀。hash 查找到 1 号块后，`touch` 看到引用为 0，将其从队列末尾摘掉，引用变成 1。C 的尾部再领 5 号，于是

```text
C 的块表       [1,5]
空闲队列       [6,7,4,2,3]
1 号 ref_cnt   1
```

双向链表可以在 O(1) 时间移除中间或末尾对象。

本课自测。如果 D 还活着，C 结束后会有两个可分配块 5 和 1，其中 1 有前缀缓存。新请求命中 1 并需要一个尾页时，准入总共消耗两块空闲额度。先 pin 住 1，再拿 5，就能保证命中页在这次分配中继续受保护。
